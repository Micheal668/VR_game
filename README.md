# Lunar Escape VR

基于上级目录《VR游戏详细执行方案.md》的 Unity 游戏工程。

## 当前里程碑：连续月面、平滑上升与手动对接

当前主场景为 **10_LunarStation_Docking**。维修 → 警报 → 选最多 3 类物资 → 月面登舱 → 双人舱启动 → 前 3 秒垂直上升 → 持续上升并逐渐转平 → 基地爆炸与损伤处置 → 入轨修正 → 手动接近轨道器 → 近距离辅助与接口锁定 → 对接结算。

修复了物资架被外部连廊碰撞体挤入、物品弹落的问题；腰前收纳框支持在框口上方松手后自然落入。近景基地和凹凸地形继续保留，远处网格沿同一月球曲面延伸，升空时不再露出原来方形地图的边缘。在轨纹理缓慢移动，速率可在 Inspector 调整。

前方轨道器为真实 3D 原型。玩家按住面板按钮产生平移或转动推力，松手后保留惯性，使用制动减速。主燃料与 RCS 燃料分别计量；仅在足够近、偏移较小且已减速时启用辅助。高速撞击、未对齐接触、偏离过远、RCS 耗尽和原有生命资源耗尽都能失败。NPC 继续只承担同乘展示，跟随和救援剧情以后接入。

Mac 模拟器的第一人称/头部模式通过玩家碰撞行走，WASD 不穿墙；Q/E 在手柄模式移动手柄。月面重力为向下 **1.62 m/s²**。登舱后固定游戏内身体，保留自然头手追踪。上升仍是时间压缩的程序轨迹；对接使用相对位置、速度和姿态积分，当前不计算完整轨道会合力学。

这是 Phase 1 的第七小步。完整操作、失败阈值和调参位置见 [第七步：连续月面与手动对接](Docs/第七步_连续月面与手动对接.md)，制作边界见 [月面与上升器实现约定](Docs/月面与上升器实现约定.md)。

## 开发环境

- 编辑器：**6000.6.1f1 / Apple silicon**。沿用本机已安装的 Unity 6.6；与设计文档建议的 Unity 6 LTS 存在版本差异。Mac 和 Windows 打开工程时必须使用相同完整版本号。
- 渲染：URP（通用渲染管线，即 Unity 绘制画面的方案），采用编辑器自带官方模板。
- 输入：Unity Input System（将键盘、鼠标、手柄输入交给游戏的官方工具）。
- 交互：XR Interaction Toolkit（Unity 官方 VR 抓取、射线、移动组件）。
- 目标设备：学校的 **HTC VIVE Pro Eye + Windows PC + SteamVR**。用户提供的展板写 Vive Pro，首次真机测试时核对实际头显及手柄型号。
- OpenXR 是游戏连接 VR 运行环境的统一接口；SteamVR 是 Windows 端管理头显、手柄和基站的运行软件。首版验证头部定位、VIVE 手柄抓取、传送和分段转向；眼动功能尚未纳入首阶段。
- Mac 当前用途：无头显的编辑器模拟与场景开发。模拟器通过不等于真实头显通过。

## 协作规则

共享 `Assets`、`Packages`、`ProjectSettings` 和其中的 `.meta` 文件；`.meta` 是 Unity 追踪资源引用的标识文件，必须随资源一起保存。

不要在两台电脑间同步 `Library`、`Temp`、`Logs`、`UserSettings`。它们由各自电脑重新生成。

每次只推进一个可验证的小目标。版本、包版本和验收结果以实际工程及后续运行说明为准。

## 代码注释要求

自写 C# 代码使用清晰中文注释，解释脚本职责、关键参数、事件生命周期和实现原因。每个组件只处理一类职责；通过显式引用和事件连接，避免全局单例与每帧场景搜索。维修逻辑不依赖界面或语言，文案集中在 JSON 中，时长、范围与工具类型在 Inspector 中配置。优先复用已有组件，再按实际需求扩展。Unity 官方组件与样例保留原始内容，方便升级对照。

## 本地依赖包

当前网络下 Unity 包管理器访问官方源不稳定，因此 `LocalPackages` 保存五个从 Unity 官方下载的原始组件包，使用相对路径引用。将工程复制到 Windows 时必须保留此目录。来源、版本及校验记录见 `LocalPackages/sources.json`。其余 URP 模板依赖仍需首次联网下载。本项目不修改全局网络代理。
