# Lunar Escape VR

基于上级目录《VR游戏详细执行方案.md》的 Unity 游戏工程。

## 切换键鼠与 VIVE 测试模式

详细步骤见 [键鼠与 VIVE 测试模式切换](README_键鼠与VIVE测试模式.md)，包含 Project Settings 菜单路径、场景模拟器开关、SteamVR 配置及常见问题。

先停止 Play。键鼠测试时取消 `Initialize XR on Startup` 并启用场景中的 `XR Interaction Simulator - Editor Only`；VIVE 测试时勾选启动选项并关闭整个模拟器对象。两种模式都保持 `Use XR Interaction Simulator in scenes` 关闭，使用项目已有的场景配置。

## 当前版本：v0.3 生命保障与实体驾驶舱

当前主场景为 **11_LunarStation_LifeSupport**，场景 10 保留。警报中从卧室醒来 → 卧室门故障、队友被困 → 工程舱接三色电路与修复制氧机 → 实验室模块配对、中控解锁 → 两人分别穿服 → 修好气闸、沿头盔路线撤离 → 左侧驾驶屏启动、入轨与对接 → 乘员结局及评分。

基地与宇航服资源每轮随机；无氧会窒息，宇航服断电会关闭 HUD、加速耗氧，并在暴露时导致昼热夜冷的体温危险。地面与飞船共用同一物资清单。新驾驶舱保留舷窗，中屏显示真实前视摄像机画面，左屏提供驾驶操纵，右屏显示百分比、剩余时间与舱温。操作和参数见 [第十一步：生命保障与实体驾驶舱](Docs/第十一步_生命保障与实体驾驶舱.md)。沿用使用者当前的键鼠与 VIVE 设置。

场景 11 新增卧室、实验室和工程舱，大厅圆桌与实验室样本各随机生成 1–3 件物品。基地氧气和电量每轮为 50–80%；接错电路只扣基地电量，应急灯共用该电量。队友获救后独立走到衣架穿服；玩家提前穿服不会替队友换装。气闸阀门方向与目标随机，转过头实际漏氧；锁销支持短暂扳手接触。开门后未穿服者 5 秒窒息。

保留的场景 10 使用手动救援流程：警报后，靠近指挥官并持续握住黄色解锁把手5秒，或按住旁边的救援按钮。指挥官获救后沿固定撤离路线跟随；在登舱区等他实际到达才会共同上船。医疗包须真正在手中、贴近胸前接口并主动使用，才会消耗并治疗。舱内另有指挥官医疗按钮，与玩家使用同一物资清单。操作、计分和当前边界见 [第十步：指挥官救援与任务评分](Docs/第十步_指挥官救援与任务评分.md)。

成功对接或失败时，统一结算三名乘员的实际结果、飞行操作、基地维护、带回科研、应急处置和资源储备。六项满分10000；原方案建议权重合计9600，本版把差额400补到乘员生还项（3900）。这是月面撤离至对接阶段评分，返航与再入尚未实现。

已接入用户提供的地球和星空照片，月面、升空和轨道对接共用天空。观察位置、地球大小与星空亮度调整见 [第八步：月面与轨道地球、星空外景](Docs/第八步_月面与轨道地球外景.md)。

修复了物资架被外部连廊碰撞体挤入、物品弹落的问题；腰前收纳框支持在框口上方松手后自然落入。近景基地和凹凸地形继续保留，远处网格沿同一月球曲面延伸，升空时不再露出原来方形地图的边缘。在轨纹理缓慢移动，速率可在 Inspector 调整。

前方轨道器已重新建模，具备清晰的对接口和三级LOD。玩家按住面板按钮产生平移或转动推力，松手后保留惯性，使用制动减速。主燃料与 RCS 燃料分别计量；仅在足够近、偏移较小且已减速时启用辅助。高速撞击、未对齐接触、偏离过远、RCS 耗尽和原有生命资源耗尽都能失败。指挥官的受困、伤势、登舱和生还由规则决定；轨道驾驶员保留为状态记录，尚无可进入的轨道器内部。

Windows/Mac 键鼠模拟器在第一人称、头部及手柄操作模式下均使用 WASD 行走，保留玩家碰撞；Q/E 在手柄模式上下移动手柄。运行后先点击 Game 游戏画面获取键盘焦点。月面重力为向下 **1.62 m/s²**。登舱后固定游戏内身体，保留自然头手追踪。上升仍是时间压缩的程序轨迹；对接使用相对位置、速度和姿态积分，当前不计算完整轨道会合力学。

主场景已接入用户提供的橙色 ACES 航天服，替换同乘 NPC，并为玩家增加跟随头手位置的身体与手臂。来源与使用边界见 [第九步：乘员模型与键盘移动](Docs/第九步_乘员模型与键盘移动.md)。

当前补齐开发方案中 Crew State 与 Scoring 的核心闭环。既有飞行操作和阈值见 [第七步：连续月面与手动对接](Docs/第七步_连续月面与手动对接.md)，制作边界见 [月面与上升器实现约定](Docs/月面与上升器实现约定.md)。

## 开发环境

- 编辑器：**6000.6.1f1**，当前验证环境为 Windows，原 Mac 环境为 Apple silicon。沿用已安装的 Unity 6.6；与设计文档建议的 Unity 6 LTS 存在版本差异。Mac 和 Windows 打开工程时必须使用相同完整版本号。
- 渲染：URP（通用渲染管线，即 Unity 绘制画面的方案），采用编辑器自带官方模板。
- 输入：Unity Input System（将键盘、鼠标、手柄输入交给游戏的官方工具）。
- 交互：XR Interaction Toolkit（Unity 官方 VR 抓取、射线、移动组件）。
- 目标设备：学校的 **HTC VIVE Pro Eye + Windows PC + SteamVR**。用户提供的展板写 Vive Pro，首次真机测试时核对实际头显及手柄型号。
- OpenXR 是游戏连接 VR 运行环境的统一接口；SteamVR 是 Windows 端管理头显、手柄和基站的运行软件。首版验证头部定位、VIVE 手柄抓取、传送和分段转向；眼动功能尚未纳入首阶段。
- Mac 当前用途：无头显的编辑器模拟与场景开发。模拟器通过不等于真实头显通过。

## 协作规则

共享 `Assets`、`Packages`、`ProjectSettings` 和其中的 `.meta` 文件；`.meta` 是 Unity 追踪资源引用的标识文件，必须随资源一起保存。

不要在两台电脑间同步 `Library`、`Temp`、`Logs`、`UserSettings`。它们由各自电脑重新生成。

每次只推进一个可验证的小目标。版本、包版本和验收结果以实际工程及后续运行说明为准。

## 代码注释要求

自写 C# 代码使用清晰中文注释，解释脚本职责、关键参数、事件生命周期和实现原因。每个组件只处理一类职责；通过显式引用和事件连接，避免全局单例与每帧场景搜索。维修逻辑不依赖界面或语言，文案集中在 JSON 中，时长、范围与工具类型在 Inspector 中配置。优先复用已有组件，再按实际需求扩展。Unity 官方组件与样例保留原始内容，方便升级对照。

## 本地依赖包

当前网络下 Unity 包管理器访问官方源不稳定，因此 `LocalPackages` 保存五个从 Unity 官方下载的原始组件包，使用相对路径引用。将工程复制到 Windows 时必须保留此目录。来源、版本及校验记录见 `LocalPackages/sources.json`。其余 URP 模板依赖仍需首次联网下载。本项目不修改全局网络代理。
