# 登月舱模型来源与场景约定

08 与当前 09 场景的上升器外观采用 NASA 发布的 **Apollo Lunar Module** 静态模型。来源页署名为 **NASA / Michael D. Carbajal**：[NASA 模型页面](https://science.nasa.gov/3d-resources/apollo-lunar-module/)。原始文件保存为 `Assets/_LunarEscape/Art/ApolloLM/ApolloLunarModule.glb`。

- [NASA 原始 GLB 下载](https://assets.science.nasa.gov/content/dam/science/cds/3d/resources/model/apollo-lunar-module/Apollo%20Lunar%20Module.glb)。
- SHA-256：`379101dfcee399267addf771709107c35e826b0b9e5233272f123e4c8a585c4e`。
- 模型合并为 12 组材质，64,787 个顶点、97,588 个三角形；保留原有梯子、四条支腿、上下两级、天线和舱门。贴图 PNG 从 GLB 原样提取；转换时只适配网格坐标、三角面方向与 UV 方向。
- 游戏统一缩放至总高 7 m，支腿跨度约 8.98 m。这是本场景的比例设定，不能视为所有阿波罗登月舱零件的工程尺寸复刻。舱内仍沿用可交互原型。
- `source.json` 保存原始来源、校验值与统计。NASA 标识和国旗是原始历史模型内容，不表示 NASA 认可或参与本课程项目。

## 为什么 Windows 不需要额外安装模型插件

原始 GLB 的网格使用 Draco 压缩。开发时先用 `Tools/convert_apollo_lm.py` 解压并合并同材质网格，生成 `ApolloMeshes.bytes`，再由 `Editor/ImportApolloModel.cs` 生成 Unity 原生 Mesh、Material 和 Prefab。生成后的资源已随工程保存，正常打开或运行无需 Python、Draco 或 glTF 插件。

需要重新生成时才使用独立 Python 环境（本次 Python 3.10，DracoPy 2.0.0、NumPy 2.2.6）运行转换脚本，再在 Unity 调用 `ImportApolloModel.Import()`。导入器默认复用已有 Prefab；若修改源模型，需先备份并清理旧的生成资源再重新导入。

## 舱门、基地与飞行视角

基地中心在原点附近；着陆器位于 `(48, 0, 1.7)`，舱门面向 -Z，基地出口面向 +X。玩家沿路线绕到 `(48, 1.2, -4.3)` 附近的梯子前，再抬头点击门上的按钮或用 VR 射线选择门。三个室外传送面仅在撤离阶段开放，没有舱内落点。

窗外基地复制地面基地的真实网格与米制尺度，不另做缩小版本。飞行使用统一的外界坐标变换，先短暂垂直上升再倾斜，并保持侧窗能观察基地；相机自然追踪与面板操作不由飞行轨迹改写。

真实阿波罗也包含垂直离地后的俯仰程序；NASA 的 [Apollo 11 Press Kit](https://www.nasa.gov/wp-content/uploads/static/history/afj/ap11fj/pdf/a11-press-kit1.pdf) 描述了初段垂直上升和随后姿态机动。当前游戏采用 3 秒垂直段、30 秒演出轨迹，**并非该历史轨迹的等比例物理模拟**。

## 09 场景补充

双人版本保持约 7 m 总高，横向尺寸乘以 1.18。梯子旁增加平视的大按钮和约 5.2×5.2 m 的登舱区，原舱门入口保留；平滑飞行延伸至入轨修正。08 的原教学尺寸和结束点仍保留。NPC、月面网格及轨道远景来源见 [双人舱与月球素材来源](双人舱与月球素材来源.md)。
