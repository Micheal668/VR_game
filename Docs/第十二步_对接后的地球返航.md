# 第十二步：三人返回舱与手动再入

本次从朋友最新版 `main`（435a104）移植。第一天仍为场景12的月壤采样、清理太阳能板、回舱睡觉；第二天仍为场景11的事故、维修、钢梁切割、救援和撤离。返航只接在第二天的月球轨道对接之后。场景04–10保留原来的结束方式。

## 怎么试玩

1. 完成基地任务、登舱、起飞、圆化和对接，点击“确认转入返回舱”。黑屏期间切换身体位置，保留自然头手追踪。
2. 等待乘员就位。获救且实际登上飞船的指挥官从顶部通道进入左侧座位，轨道驾驶员在右侧；未随行的指挥官保持缺席。
3. 点击“关闭顶舱门 · 分离上升器”。顶舱门绕铰链关闭，上升器从顶部接口分离，向左前方漂离；不包含下降级、支腿或舷梯。
4. 点击“确认点火 · 返回地球”。上升器和月球相对向下远离。8秒的转移航程压缩了三天，地球按同一时间尺度自转。
5. 地球捕获制动持续5秒，时间加速逐渐结束，进入等待玩家操作的地球轨道。
6. 座椅斜上方主屏提供油门、再入夹角和左右航向调整。油门每次10%，50%为默认速度，100%点火时间减半，0%停止推进。夹角每次0.5°，绿色范围为 **5.5°–7.5°**；默认3°偏浅，需要主动调整。航向每次2°，改变舱外地球与跟踪镜头的相对方位，不额外计算落点。读数包括速度、高度、舱外温度、热盾温度、过载和结构完整度。
7. 点击“按当前角度 · 离轨点火”锁定轨道。此后经过离轨制动、服务舱分离与大气再入，不能再改角度。
8. 再入之后持续下降。屏幕左侧高度条标出 **3.2–1.8 km开伞**（绿色）和 **1.0–0.4 km抛隔热大底**（蓝色），两个窗口各约六秒。按键不会重置高度、时钟或暂停下降。三组伞从舱外肩部伞包抽出，绳索拉直后充气；主伞稳定后才允许在指定高度抛底。越过任一窗口下限仍未操作，会继续高速下落并显示返航失败。

鼠标与VR射线共用按钮。转舱、分离上升器、离月点火、再入角度确认四个准备点等待玩家操作；开始再入后，开伞和抛底都有高度期限，不等待玩家。显式点击暂停仍可暂停教学，头手追踪继续。默认50%油门时，离月点火至安全落地的自动航程约60秒，不计四个准备点和主动暂停。

右前侧小屏显示768×432实时外景：太空中跟踪真实返回舱，再入时看见包裹舱体的热流，开伞时拉远展示伞组，抛底时平滑调整构图展示底板分离，落地前保持完整伞组在画面内，最后跟踪海面降落。屏幕下方显示当前阶段。画面来自独立单目摄像机，排除UI层防止递归；重新开始会释放摄像机和渲染纹理。

## 再入结果

| 夹角 | 过程 | 最终结果 |
| --- | --- | --- |
| 小于5.5° | 减速不足，热流减弱，高度从约58 km重新升至380 km，仍保持高速 | 跳出大气、错过回收走廊，返航失败 |
| 5.5°–7.5°，含边界 | 温度与过载先升后降，速度下降，开伞并溅落 | 安全返航，显示救援阶段成绩 |
| 大于7.5° | 热盾温度、过载与结构损伤迅速上升，舱体碎片散开，伴随爆裂音与闪光 | 舱体解体，返航失败 |

上述角度、热损伤曲线和遥测是游戏参数，不是龙飞船或阿波罗的真实飞行包络。这里采用“主动制动捕获地球轨道，再由玩家离轨”的虚构任务安排，不是阿波罗直接返回的历史复现。过浅失败表达无法按计划回收，不宣称任何浅角度都会永久逃逸地球引力。

## 模型和外景

- Blender源文件：`Models/ReturnCapsule/ThreeSeatReturnCapsule.blend`。钟形压力壳约4.6米宽，顶部收窄；三张并排后仰座椅、顶部对接通道与舱门、吊臂显示器、四个独立圆形舷窗、窗框密封与压力玻璃。布局参考用户提供的龙飞船照片，非工程级复原。
- `Tools/build_return_capsule.py` 重建可编辑模型并导出修改器求值后的网格；`ImportReturnCapsule.cs` 生成Unity原生Mesh、Material和Prefab，运行游戏不需要安装Blender。
- 指挥官和驾驶员继续使用已有ACES素材，转换为座姿网格。转舱仍是位置、整体姿态动画，未制作完整抓扶手、扣安全带和全身动作捕捉。
- 返回地球改为立体球面，NASA全球经纬贴图随球体旋转；Shader补充云层、昼夜照明和蓝色边缘。原地面和对接天空照片保留。素材来源及哈希见 `Assets/_LunarEscape/Art/EarthReturn/SOURCES.txt`。
- 再入时舱外出现环绕压力舱的弯曲湍流层，窗框受到橙色照明，后段逐渐转为大气天空。舱内相机不强制晃动。
- 月球轨道上的组合体按“上升器 → 对接接口 → 白色三人返回舱 → 服务推进舱”连接，移除旧模型的灰色锥形指令舱。使用白色返回舱原有顶部通道与捕获环；对接目标和跟踪视角同步采用这一结构。服务推进舱复用现有Blender轨道器的材质与网格，原模型资产不改。分离上升器时，返回舱与服务舱保持连接；接近地球、完成离轨点火后才分离服务舱。原有对接坐标、引导圈与捕获规则保留。
- 地球半径固定，球面与海面位置都从当前高度连续计算。大气颜色和海面逐渐混合，不在开伞时隐藏地球或换到另一张背景。
- 伞组不整体缩放。每个伞包位于外壁肩部，伞衣从外部位置向上抽出后充气，绳索固定在外壁吊点。隔热底板持续向下加速离开，舱体继续下降。
- 月球、飞船和地球采用统一舱外参考系及压缩距离，未求解完整轨道力学。末段高度曲线固定压缩为22秒，遥测和操作窗口是游戏参数。

## 安装和代码

安装入口：`Lunar Escape → Install Earth Return Sequence (Life Support Scene)`。重复运行会重建返航展示对象并更新引用。基地扩建完整安装器也调用该步骤；不要手改场景YAML。

修改模型后运行：

```powershell
& C:/Tools/blender.exe -b -t 8 --python Tools/build_return_capsule.py
```

然后运行Unity安装器，更新场景和三语字体。游戏继续支持中英俄；开发说明使用中文，Git提交和PR说明按要求使用中俄双语。

`EarthReturnMission` 保存阶段、夹角、油门、航向、压缩时间、遥测和终局，`StationMissionSession` 提供唯一计时。再入以不超过0.02秒的子步积分热损伤和高度窗口判断，大帧步同样不能跳过错失窗口的失败。默认自动航程分配为：离月4秒、转移8秒、接近5秒、离轨3秒、舱段分离2秒、再入16秒、末段下降22秒，总计60秒。舱外温度读数是热流展示参数；手动抛底为用户要求的虚构玩法，不代表龙飞船实际操作流程。

`EarthReturnPresenter` 更新乘员、舷窗外景、角度走廊、声音和热流。`MissionScorePresenter` 仅在安全溅落后显示成功；返航失败显示独立失败结算，不把对接时的成功快照当作最终成功。原救援分数快照保留，便于旧场景和规则复用。

返航重开前先恢复地面事件监听，确保朋友的第二天钢梁和切割工具收到原有复位事件。重新开始会清除返航阶段、角度、航向、油门、热损伤、开伞、抛底、暂停和乘员标记，恢复场景、舱门、结构碎片、天空、座椅锁和基地总闸，并释放侧屏渲染资源。
