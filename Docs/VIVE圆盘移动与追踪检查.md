# VIVE 圆盘移动与追踪检查

适用场景：`10_LunarStation_Docking`，HTC VIVE 圆盘手柄。

## 操作

- 左右手均可：按住圆盘上半区前进，按住下半区后退。朝向以头显水平朝向为准，速度上限 1.4 m/s。
- 仅触摸圆盘不会移动；松开按压立即停止水平移动；中心及左右区域不触发行走。
- 圆盘不再触发传送、连续转向或分段转向。转身使用真实头部和身体转动。
- 扳机点选、抓取、任务流程及登舱后的移动锁定沿用原有逻辑。

输入文件位于 `Assets/_LunarEscape/Input/Lunar Vive Controls.inputactions`。它从官方样例复制，只有左右手 Move 绑定改为同时满足圆盘按压和有效追踪；官方样例文件没有修改。

## 手臂显示

有效追踪时，视觉手臂估算肩、肘、腕位置；不修改真实头显、手柄或交互射线。丢失位置或旋转追踪时，手臂平滑回到身体两侧的模型初始姿态。手臂增加平滑、稳定肘部朝向及手腕转角限制，保留骨骼长度，避免强行拉长袖口。

该航天服来自无原生骨骼的模型，手臂长度和绑骨是估算值。控制器超出模型臂长时，视觉手掌会停在可达范围内，真实交互点仍随手柄。真机上仍需检查握姿和臂长匹配；这不是完整人体追踪。

## 真机复测

1. 使用更新后的主场景。整个 `XR Interaction Simulator - Editor Only` 保持关闭，包含其设备生命周期及手部模拟组件。
2. Windows OpenXR 使用 Multi Pass，并启用 HTC Vive Controller Profile。
3. 分别测试左右圆盘：触摸、按上半区、按下半区、松开后继续触摸、按左右边缘；确认上述操作符合预期。
4. 不碰手柄，静置头显，观察 30 秒；再自然垂下双手、抬手、转腕，检查姿态。
5. 遮住一个手柄使其失去追踪，确认对应视觉手臂回到侧边；恢复追踪后再次抬手。
6. 扳机操作任务面板、抓取维修工具；登舱后确认圆盘不能移动身体，而头手仍可追踪。

若头显静置仍会转动，退出游戏，在 SteamVR 环境中做同样测试：SteamVR 中也漂移则继续排查基站遮挡、反光和追踪状态；只在游戏中出现则记录发生阶段、是否进入飞行，以及整个模拟器是否关闭。当前修正排除了主场景圆盘转向入口，不能据此证明硬件追踪已正常。

配置入口：`Lunar Escape > Configure Vive Press To Walk`。更新主场景已保存，正常使用无需重复执行；重新生成主场景后可用此入口恢复配置。它保留官方样例，不重建房间。

## 本地验证（2026-09-25）

Unity 6000.6.1f1 编译通过。3 项 `ViveControlsTests` 全部通过：官方 Vive 输入布局下的双手按压/触摸/追踪丢失/断开、场景真实移动与停止及转向禁用、骨骼长度和失去追踪后的回位。16 项 `DockingSceneTests` 回归全部通过，包括键盘模拟行走碰撞、乘员模型、飞行、对接及重试流程。

结果保存在本机 `Logs/ViveTestsGraphics.xml`（新增三项通过；该轮旧截图测试因目录缺失失败）及 `Logs/ViveDockingRegression.xml`（补齐截图目录后，原有 16 项全部通过）。测试未连接真实头显，不代替真机追踪和手臂握姿验收。用户反馈 SteamVR 待机环境稳定、只有游戏内乱转；更新后应优先复测游戏静止视角。
