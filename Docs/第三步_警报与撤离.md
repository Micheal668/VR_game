# 第三步：警报与撤离

这一课把上一课的维修接入一段完整的撤离演练。先认识任务顺序，再实际走一次。

**开始演练 → 氧气维修 → 短暂恢复 → 最终警报 → 穿过右侧舱门 → 上升器入口 → 本段完成**

维修未完成也会触发最终警报，但可用撤离时间更短。当前只是 Phase 1 中的一段原型，尚未包含完整游戏的资源选择、飞行和结算。

## 1. 打开场景，开始演练

Unity 顶部菜单选择 **Lunar Escape → Open Evacuation Scene**，打开 `Assets/_LunarEscape/Scenes/06_LunarStation_Evacuation.unity`，点击 **Play**。

先点击 **Game** 画面使其接收键盘输入。初始处于准备阶段，不计时；可以先看说明、切换中文 / English / Русский。

**Mac 操作：按 `H` 选择头部模式，再用鼠标点击“开始演练”。** 从手柄模式切回 `H` 后，也可以点击语言或重试按钮。官方模拟器在手柄点选模式中会接管鼠标，不能把这时的鼠标点选等同于普通界面点击。

**完成标准：** 开始前时间不减少；点击开始后，出现氧气故障提示，维修倒计时从约 `01:30` 开始。

## 2. 修好氧气设备，观察警报

按上一课的方法拿住工具，把白色工具头保持在氧气设备的维修点附近，累计有效接触 **2 秒**。移开或松手会暂停维修进度；仅把工具丢在维修点上不会维修。

- `]` 选择右手柄，`[` 选择左手柄；手柄模式下用 `W/A/S/D` 和 `Q/E` 调整工具位置，`G` 模拟握持，也可以使用模拟器的鼠标点选操作。
- 第一人称或 `H` 头部模式下，`W/A/S/D` 沿地面行走，墙壁与桌子会挡住身体；`Q/E` 不会让玩家上下飞行。
- 操作时使用英文输入法；需要查看当前输入模式时可按 `Y`。

本课有两条结果：

**90 秒内修好 → 氧气恢复 → 等待 4 秒 → 警报 → 90 秒撤离时间**

**90 秒维修窗口用尽仍未修好 → 立即警报 → 60 秒撤离时间**

成功维修增加 **30 秒**撤离时间，但无法阻止最终事故。屏幕上的提示、警报灯和轻提示音会说明当前阶段；警报开始后，右侧实体舱门打开。

**完成标准：** 修好后能看见短暂恢复阶段和时间奖励；不维修时也会进入警报。进入撤离阶段后，面板不再催促继续维修。

## 3. 沿右侧通道撤离，再试一遍

切回 `H` 或第一人称模式，用 `W/A/S/D` 穿过右侧舱门，走到通道末端的**青色地面集结标记**。那里代表上升器入口；身体需要实际进入区域，只把工具扔进去或伸手进去不会完成。

**倒计时结束前进入 → 本段完成，显示抵达时剩余时间**

**撤离倒计时归零 → 死亡 / 任务失败 → 弹出结算窗口 → 只能重新开始**

这里的“本段完成”只表示已到达上升器入口，尚未起飞。正常任务中的主面板和入口面板都有“重新演练”按钮。

撤离超时后，结算窗口会出现在当前视线前方，显示死亡原因和本轮氧气维修结果。这时不能行走、传送、抓取工具或点击背后的语言/任务按钮；只保留窗口的“重新开始”。Mac 模拟器会把鼠标交回界面，无需先切到头部模式。VR 头部与手部追踪继续工作，方便看清窗口并用射线点选。

点击“重新开始”后，人物回出生点，工具、舱门、警报和计时复位，恢复游戏操作；当前语言保持，并回到不计时的准备阶段。死亡前尚未执行的传送会取消，防止重开后突然跳走。

注意：维修窗口结束仍按原规则进入撤离阶段；触发死亡的是**撤离倒计时**归零。

**完成标准：** 完成一次正常撤离，再尝试一次超时失败；重试后能从头再次完成，当前语言保持不变。

只想快速检查死亡结算时，可以在 **Play** 中选择 **Lunar Escape → Preview Failure Summary (Play Mode)**。该编辑器入口会从出生点重新开始并快进任务计时，不修改时长配置，也不会出现在发布的游戏中。

## 这些参数在哪里调整

停止 **Play**，在 **Project** 资源面板找到并选中：

`Assets/_LunarEscape/Settings/Station Mission.asset`

在右侧 **Inspector** 属性面板中可修改：

| 字段 | 当前暂定值 | 含义 |
|---|---:|---|
| Repair Window Seconds | 90 | 开始后允许维修的时间 |
| Stabilized Seconds | 4 | 修好后、警报前的恢复时间 |
| Base Evacuation Seconds | 60 | 没有维修奖励时的撤离时间 |
| Repair Bonus Seconds | 30 | 及时修好的额外撤离时间 |

这些是方便学习与测试的原型参数。维修需要的 **2 秒有效接触**仍在场景里的 **Oxygen Repair Station → Timed Repair Task → Duration Seconds** 中设置；它与上面的“允许维修时间”是两个不同概念。

## 这一课先读哪些代码

先读 `StationMission.cs`，理解“当前处于哪个阶段，以及什么条件会进入下一阶段”。其余脚本按职责配合：

| 文件 | 负责什么 |
|---|---|
| `StationMissionConfig.cs` | 保存可调整的演练参数 |
| `StationMission.cs` | 管理阶段、时间、维修奖励和结果 |
| `StationMissionSession.cs` | 读取场景中的接触与到达条件，协调重试 |
| `EvacuationZone.cs` | 判断玩家身体中心是否进入撤离区域 |
| `MissionEnvironment.cs` | 根据任务阶段更新舱门、警报灯和声音 |
| `MissionPresenter.cs` | 显示三语任务说明、倒计时和按钮 |
| `MissionFailurePresenter.cs` | 显示死亡结算窗口与唯一的重新开始按钮 |
| `MissionFailureLock.cs` | 失败时停止游戏操作，重试后恢复，保留头手追踪与结算输入 |
| `MissionTeleportationProvider.cs` | 取消失败前在途传送，避免重试后执行旧请求 |
| `TimedRepairTask.cs` | 复用上一课的维修进度、暂停和完成逻辑 |

本课由同一个 `Tick` 调用统一推进任务计时和维修。`Tick` 可以理解成“让规则前进一小段时间”：这样不会出现两个脚本分别计时，导致“维修完成”和“倒计时归零”争先发生。规则层不读取界面；界面只展示规则得出的状态。

Mac 模拟器用于练习流程。学校的 **HTC VIVE Pro Eye** 仍需在 Windows 上验证真实手柄输入、传送、门洞通过、声音、舒适性与性能。后续再加入三类撤离资源的选择、队友、起飞与基地爆炸，以及评分。
